# 提示词速查

> 复制改动后直接发给 WorkBuddy。方括号替换成实际情况。
> 配合「两阶段工作法」：先讨论（Plan），确认后再说"改吧"。

## 1. 新功能：先讨论

```
我要给 PlaneWar 加【功能名】。
背景：目前【现状描述】。
约束：Cocos Creator 3.8.7，脚本在 assets/scripts/，子弹走对象池。
要求：先给 2~3 种实现方案，说清每种的代价和收益、你推荐哪个及原因。
不要直接写代码，我确认方案后你再动手。
```

## 2. 重构

```
重构 assets/scripts/【entities|managers|data】/【文件】。
目标：【例如 把三个敌机 prefab 合并成一个 + 配置】。
要求：先列出当前依赖关系和拆分思路，确认后再改。
改完列出：改了哪些文件、每处为什么改、编辑器里我要手动做什么。
```

## 3. Bug 定位

```
运行时报错：【完整错误信息】。
复现步骤：【步骤】。
相关文件：assets/scripts/xxx/yyy.ts
要求：先读文件定位真正原因，再解释为什么会触发，最后给最小改动方案。
不要一上来就大改，也不要猜 API。
```

## 4. 代码审查

```
审查 assets/scripts/【路径】。
重点看：空引用风险、update 里的开销、对象池有没有漏回收、init 有没有完整复位、
生命周期用错（onLoad 里依赖他人）、有没有用到 Cocos 2.x 的老 API。
按严重程度排序输出问题清单，每条给出具体行号和修改建议。
```

## 4.1 组件生命周期审查

```
按 .workbuddy/memory/cocos-lifecycle.md 审查 assets/scripts/【路径】的组件。
逐项检查：onLoad 里有没有异步或依赖他人状态；事件是否 onEnable/onDisable 成对；
await 后有没有检查 node.isValid；update 里有没有分配对象或查找节点；
有没有依赖场景节点排列顺序。输出违反项 + 具体行号 + 改法。
```

## 5. 讲清一个引擎概念（新手模式）

```
讲清楚 Cocos 的【对象池 / 物理碰撞 / prefab / 生命周期 / resources 加载】。
我是新手，先从机制本身讲起：它解决什么问题、引擎内部大概怎么跑的。
然后给一个能直接跑起来的最小例子，最后说明在 PlaneWar 里该用在哪。
```

## 6. 改完代码后的收尾

```
这次改动涉及资源或 prefab，列出我在 Cocos 编辑器里要做的全部操作。
```

```
今天做了什么记一下，写到项目记忆里。
```

## 7. 生成美术素材

```
生成 PlaneWar 的【玩家飞船 / 敌机 / 子弹】sprite，纵版射击风格，机头朝上，
【像素 / 卡通】风格，透明背景 PNG，尺寸 128x128。
```

## 常用开关

| 想让 AI 怎么样 | 直接说 |
|---|---|
| 只出方案别改文件 | "只输出方案，不要改任何文件" |
| 已经确认，开始落地 | "改吧" / "实现吧" |
| 只要结论不要长篇 | "用表格+要点，不要长篇解释" |
| 怀疑某个约定过时 | "这条约定还成立吗？给出复核结论" |
