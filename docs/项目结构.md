# PlaneWar 项目结构（代码地图）

> 描述当前代码的真实形态。设计理由见 `架构决策.md`。

## 一、脚本清单（35 个 .ts，全部在 `assets/scripts/`）

```
assets/scripts/
├── GameEntry.ts              启动入口：加载机型资源 → 初始化监听 → 进入菜单
│
├── core/                     基础设施，与玩法无关
│   ├── EventBus.ts           全局事件总线（模块单例）
│   ├── ObjectPool.ts         单 prefab 对象池（封装 NodePool，capacity=300）
│   ├── PoolManager.ts        Map<Prefab, ObjectPool> + poolManager 全局单例
│   ├── WFCGenerator.ts       波函数坍缩地图生成算法（纯算法，不 import cc）
│   └── utils/
│       ├── asset.ts          getAsset / getAssetList（resources.load 的 Promise 封装）
│       └── common.ts
│
├── data/                     配置与运行时状态

│   ├── PlayerData.ts         玩家运行时数据单例

│   │   ├── EnemyConfig.ts    敌机配置表
```

## 二、分层与依赖方向

| 层 | 位置 | 规则 |
|---|---|---|
| L0 纯数据 | `GameState`、`config/*`、`WFCGenerator` | 不 import cc |
| L1 基础设施 | `EventBus`、`ObjectPool`、`PoolManager`、`utils/asset.ts` | 不依赖业务 |
| L2 数据单例 | `PlayerData` | 只存本局会变的值 |
| L3 逻辑单例 | `GameManager`、`ShipRegistry` | 可依赖 L0~L2 |
| L4 实体 | `entities/` 全部 | **不得运行时 import L5**，只 `import type` |
| L5 管理器 | `managers/` 全部 | 可持有 L4 |
| L6 UI | `ui/` 全部 | 只依赖 GameManager / PlayerData / EventBus |
| L7 入口 | `GameEntry` | 只做启动引导 |

- 循环依赖一律用 **`import type`** 打破（`Enemy` ↔ `EnemyManager`、`Bullet` ↔ `BulletManager`）。
- 分层判据是"**有没有行为**"，不是"目录里有没有 `from 'cc'`"：
  纯数值 / 纯声明即使 import cc 也允许（如 `ShipRegistry` 只做查表与缓存）。

## 三、启动时序

```
反序列化（@property 引用全部就绪）
  → 各组件 onLoad()
      · BulletManager / EnemyManager / MapManager：订阅 state_change
      · UIManager：实例化 4 个面板并拉一次状态快照
      · ShipSelectView：读机型资源（此时可能尚未加载完成）
  → GameEntry.start()
      · await loadShipAssets()      并发加载三个机型的资源并写入缓存
      · emit 'ship_assets_ready'    ShipSelectView 收到后补一次刷新
      · gameManager.initListeners()
      · setGameState(MENU)
  → 每帧 update()
```

**关键约束**：`onLoad` 早于 `GameEntry.start()`，异步资源此时尚未就绪。
启动时就要读机型资源的组件，必须订阅 `ship_assets_ready` 补刷新，不能假设资源已存在。

组件生命周期的完整规范（`onLoad` / `start` 职责、事件订阅配对、`await` 后校验节点有效性等）
见 `.workbuddy/memory/cocos-lifecycle.md`。

## 四、核心数据流

### 射击链路（每帧）

```
Player.update
  → 组装 FireContext { fireLevel, x, y, bulletContainer, beamLayer, mods, bulletPrefab }
  → for (e of emitters) e.tick(dt, ctx)
       · LaneEmitter：冷却到点 → spawnBullet(x, y, params, ctx.bulletPrefab)
       · BeamEmitter：线段 / 矩形持续检测，不产生 Bullet
  → BulletManager.spawnBullet(..., prefab) → poolManager.acquire(prefab, container)
  → Bullet.init(manager, params, prefab)   记住自己的 prefab，决定回收进哪个池
```

### 伤害链路

```
Bullet 命中 → Enemy.onBeginContact → Bullet.getDamage()
  → Enemy.takeDamage() → emit enemy_die { score }
  → GameManager.onEnemyDie → addScore(score)
```

### 事件总线

| 事件 | 发布者 | 订阅者 |
|---|---|---|
| `state_change` | GameManager（唯一发布） | Player / Enemy / Bullet / 各 Manager / GameResultView |
| `player_data_change` | PlayerData 的写方法 | GameHUD / Player / ShipSelectView |
| `ship_assets_ready` | ShipRegistry（加载完成后） | ShipSelectView |
| `enemy_die` | Enemy | GameManager |
| `player_hit` | Enemy | GameManager |

多实例组件订阅**必须传 context（`this`）**，否则只有第一个实例能订阅上。

## 五、状态机

`MENU` / `PLAYING` / `PAUSED` / `OVER`

- **PLAYING ↔ PAUSED 保留进度**（计时余量、位置、速度），其余迁移一律清零。
- 计时类组件（EnemyManager）：暂停迁移时直接 return，不碰 timer。
- 位移类组件（Enemy）：`update` 首行 `if (isPaused) return`，位置自然保留在节点坐标上。

## 六、资源目录约定

```
assets/
├── resources/              运行时按 id 动态加载（走 resources.load）
│   ├── ships/<shipId>/     机身图 / 子弹 prefab / 音效
│   └── common/             各机型共用的子弹 prefab
├── prefabs/                被 @property 拖住或被场景直接引用（不进 resources）
│   ├── entites/            Player / Enemy_Normal / Enemy_Elite / Enemy_Boss / Bullet_1
│   └── ui/                 Menu / HUD / GamePause / GameResult
├── Tilemap/ Tiles/         地图瓦片图集（被 MapManager 静态引用）
└── scenes/Game.scene
```

**进不进 `resources/` 的判据**：

- 需要按 id 动态取用 → 进（子弹、敌机、将来的特效）
- 被 `@property` 拖住或场景直接引用 → 不进（存 uuid，与目录位置无关；
  移进去会无条件进首包且失去构建期裁剪）

**`resources.load` 的三条硬规则**：路径不带扩展名；`SpriteFrame` 要写 `xxx/spriteFrame`；
resources 内的资源可以引用目录外部资源，依赖会一起导出。

## 七、编辑器接线清单

代码改完后必须在编辑器里人工完成的部分：

| # | 位置 | 操作 |
|---|---|---|
| 1 | 工程设置 / `GameEntry` | 开启 2D 物理系统，否则刚体不动、不碰撞 |
| 2 | `Player.prefab` | 挂 `Player.ts`，拖 `beamLayer`（不拖则激光不显示） |
| 3 | `BulletContainer` 节点 | 挂 `BulletManager.ts`（无 `bulletPrefab` 字段，prefab 由代码注入） |
| 4 | `EnemyContainer` 节点 | 挂 `EnemyManager.ts` |
| 5 | `Map` 节点 | 挂 `MapManager.ts`，拖 waterFrame / grassFrames / sandFrames |
| 6 | `UI` 节点 | 挂 `UIManager.ts`，拖 4 个面板 prefab |
| 7 | 常驻节点 | 挂 `WaveManager.ts`（波次驱动，不挂则无波次、无法通关） |
| 8 | 常驻节点 | 挂 `VfxManager.ts`（监听 `enemy_die` / `enemy_hit` 播特效） |
| 9 | 常驻节点 | 挂 `DropManager.ts`，拖 `pickupPrefab` + `pickupSprites`（4 张图标，顺序 WEAPON_UP/RAMPAGE/HEAL/SHIELD） |
| 10 | `assets/resources/ships/<id>/` | 放机身图 / 子弹 prefab；`assets/resources/common/vfx/` 建 `Explosion.prefab` / `Hit.prefab`；`Pickup` 组件重挂（原 PowerUp.prefab 改名） |

> 完整接线步骤（含碰撞分组矩阵、VFX/Pickup prefab 细节）见根目录 `README.md` 的「运行与构建」一节。

容器节点（BulletContainer / EnemyContainer / Map）必须**位置 (0,0)、scale (1,1,1)**，
否则子节点局部坐标被缩放，出生点与边界判定全部错位。
